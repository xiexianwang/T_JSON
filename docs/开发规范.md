# T-JSON 开发规范

本文件是开发 T-JSON 客户端时必须遵守的强制约束，分三部分：
1. **编码与协议规范**（原 `docs/rule.md`）
2. **UI 与布局约束**（原 `docs/ui_rule.md`）
3. **Agent 工作原则**（原 `docs/agent.md` 约束部分）

协议速查见 `ARCHITECTURE.md` §6，Pelco-D 指令包见 `docs/指令.md`。

---

## 1. 编码与协议规范

### 1.1 技术栈要求

- **编程语言**：C++17 或更高版本
- **核心框架**：Qt 6.x（Core、Network、WebEngineWidgets、WebChannel、SerialPort）
- **构建系统**：CMake

### 1.2 协议规范

- **通信架构**：客户端（Client/Computer）连接服务端（AI Camera/Server）
- **通信端口**：默认 TCP 8089 进行信令和状态通信
- **字节序**：默认网络字节序（**大端 Big-Endian**，`0xEC 0x91` 标准帧的 4 字节长度字段）。⚠️ 协议约定特例：48M-Tofu7 图像分包等特定帧头使用**小端**，当前代码尚未实现，开发时须按帧类型区分
- **标准帧结构（7 字节包头）**：
  - Byte 1：`0xEC`（标识码 1）
  - Byte 2：`0x91`（标识码 2）
  - Byte 3：Frame Type（如 0x01、0x03、0x11 等）
  - Byte 4-7：Payload Length N（4 Bytes，uint32 大端）
  - Byte 8...：Payload（JSON 数据或纯二进制数据）

### 1.3 Qt 开发规范

- **网络通信**：必须使用 `QTcpSocket`。严禁阻塞模式，所有网络操作采用异步信号槽（`readyRead`、`connected`、`disconnected`、`errorOccurred`）
- **TCP 粘包/半包处理**：TCP 是流式协议，不能假设每次 `readyRead` 读到完整协议帧。必须维护接收缓冲区（`QByteArray buffer`）：先检查缓冲区是否满 7 字节 → 解析长度 N → 检查是否满足 `7 + N` 字节 → 完整才提取处理并从缓冲区移除
- **JSON 处理**：使用 `QJsonDocument` / `QJsonObject` / `QJsonArray`
- **内存与性能**：图片等大量二进制操作避免不必要的深拷贝

### 1.4 心跳与重连

- **心跳 `0x11`**：客户端周期发送 10s（`m_heartbeatTimer`）。⚠️ 目标态：服务端 15s 未收到心跳回复断开连接；客户端也应实现接收心跳超时检测（当前仅发送心跳，尚未实现接收侧超时判定断线）
- **ACK `0x12`**：双向通信需响应 ACK 确认（心跳除外，心跳回心跳包）
- **自动重连**：指数退避（2s→4s→…→60s 封顶），上限 10 次，超过上限停止重连并通知 UI（`reconnectFailed`）

### 1.5 代码结构

- **模块分离**：网络通信层与 UI 层严格分离，通过信号把解析后的数据传给上层
- **枚举定义**：使用 `enum class` 强类型枚举定义帧类型与工作模式：

```cpp
enum class FrameType : quint8 {
    Status = 0x01,       // 状态帧 (S->C)
    Control = 0x03,      // 控制指令 (C->S)
    Heartbeat = 0x11,    // 心跳 (双向)
    Ack = 0x12           // ACK (双向)
};
```

### 1.6 消息载荷规范

- 发往相机的控制指令严格按协议规定的 JSON Key 构建（如 `"ControlType"`、`"WorkMode"`），注意大小写与层级嵌套
- 代码添加完善的 `qDebug()` / `qWarning()` 打印，方便追踪收发完整报文头部（不推荐打印超长 JSON 负载），妥善处理网络断开与重连逻辑

## 2. UI 与布局约束

### 2.1 产品定位与框架选择

- 软件交付**终端客户**使用，非开发调试工具。界面必须干净、直观、业务导向。**严禁**在 UI 面板暴露底层网络协议的原始报文（RX/TX HEX 数据流、原始 JSON 字符串）
- **UI 框架**：强制 Qt Widgets (C++)，主窗体继承 `QMainWindow`

### 2.2 整体布局规则

采用**固定全景布局（Fixed Dashboard Architecture）**：放弃多页签和滚动条，在 CentralWidget 静态分块，用户打开软件同一屏幕内一览所有操作与状态。

- **顶部栏（Top Bar）**：设备连接配置（IP、端口）与全局连接状态，水平布局
- **中部核心区（Middle Area）**：
  - **左侧（Display Area）**：视频流与目标图像渲染区，占比最大化，支持 16:9 比例锁定与黑边坐标逆映射
  - **右侧（Control Panel）**：纯主动控制组件（AI 工作模式、算法切换、云台控制盘、预置位、经纬度下发），垂直紧凑布局，无滚动条
- **底部仪表盘（Bottom Dashboard）**：水平平铺 5 个等宽状态组，展示被动接收/上报数据：
  1. 云台状态（PTZ - 角度、经纬高、模式、距离）
  2. 镜头状态（Lens - 双光倍率、焦距、视场角、聚焦）
  3. 识别上报（多目标列表）
  4. 跟踪上报（单目标锁定状态）
  5. 图像与系统参数（含获取按钮与参数展示）

### 2.3 关键组件强制约束

- **业务数据展示**："识别上报"推荐 `QTableWidget` 列出多目标（ID、类别、坐标）；其余状态监控用 `QFormLayout` + `QLineEdit(ReadOnly)` / `QLabel` 键值对展示
- **参数安全边界**：向用户开放的参数必须提供输入校验，`QSpinBox` / `QDoubleSpinBox` 必须设定符合设备物理限制的 max/min，防止输入破坏性参数

### 2.4 视觉与交互风格

- **视觉焦点**：深色扁平化 QSS，降低周边控件视觉干扰，突出中央视频画面
- **现代扁平化**：摒弃 3D 凸起边框；可交互元素必须具备 Hover、Pressed、Disabled 颜色反馈
- **操作反馈与线程安全**：网络重连等耗时操作必须在后台处理，绝不阻塞 UI 线程；成功/断开必须给客户直观反馈（按钮变色、状态栏提示）

### 2.5 画面渲染与坐标映射

- **等比渲染与黑边（Letterboxing）**：画面控件强制保持原始长宽比（16:9）。主窗体拉伸时图像等比缩放（`Qt::KeepAspectRatio`），多余部分留黑边
- **UI 坐标到真实坐标的逆映射**：**严禁直接将 UI 控件鼠标坐标作为目标坐标下发给设备**。框选跟踪等点选操作必须严格映射：
  1. 取鼠标控件坐标 `(X_ui, Y_ui)`
  2. 减去等比缩放产生的黑边偏移 `(Offset_X, Offset_Y)`
  3. 除以当前渲染缩放系数 `Scale`
  4. 换算回相机原始分辨率（如 2688×1520）下绝对坐标 `(X_real, Y_real)`，再经 JSON 发送设备

## 3. Agent 工作原则

1. **优先使用 Qt 特性**：强制 `QTcpSocket`、`QTimer`（心跳）、`QJsonDocument` 等 Qt 类，杜绝混用 C++ 标准库（`std::thread`、`<sys/socket.h>`）实现网络功能
2. **严防粘包陷阱**：网络接收必须实现状态机或基于缓冲区的粘包/半包处理，绝不假定一次 `readAll()` 就是完整协议帧
3. **结构化通信**：发往相机的控制指令严格按协议 JSON Key 构建（`"ControlType"`、`"WorkMode"`），注意大小写和层级嵌套
4. **代码鲁棒性**：完善 `qDebug()`/`qWarning()` 追踪收发报文头部（不推荐打印超长 JSON 负载），妥善处理网络断开与重连
5. **架构分层**：遵守 `ARCHITECTURE.md` §3 依赖方向。UI 绝不直接调用底层网络对象，一切经 Presenter 与 EventBus 中转；`core/` 内无 UI 与平台依赖

## 4. 工程规范

### 4.1 命名约定

| 项 | 约定 | 示例 |
|---|---|---|
| 类 / 结构体 | PascalCase | `DeviceContext`、`PtzConfig` |
| 成员变量 | 前缀 `m_` + camelCase | `m_currentDelay`、`m_retryCount` |
| 成员函数 | camelCase | `sendJsonCmd()`、`handleReconnect()` |
| 常量 | 前缀 `k` + PascalCase | `kPipShowValues`、`kPipShowCount` |
| 枚举类型 | PascalCase；值 PascalCase（C++17 `enum class`） | `FrameType::Heartbeat`、`PtzDir::UpLeft` |
| 文件 | 类同名：`PascalCase.h/.cpp` | `tjsonclient.h`、`DeviceManager.cpp` |
| 信号/槽 | 事件类 `sig*`；提交类 `onXxx()` / `post*()` | `sigDeviceConnected`、`postDeviceFrameReady` |
| 宏 | `全大写 + _` | `TJSONCLIENT_H`、`ENABLE_S3_UPLOAD` |

### 4.2 日志与调试

- **分级**：`qDebug()` 常规流程（收发报文头）；`qWarning()` 异常但不致命（粘包丢弃、参数越界、重连失败）；`qCritical()` 致命错误（模块初始化失败、资源分配失败）
- **禁止**：打印完整长 JSON/JPEG 载荷；在 Release 中遗留敏感信息（设备口令等）
- **调试窗口**：指令日志 `CmdLogDialog` 属调试功能，第二阶段剥离（条件编译）

### 4.3 内存与生命周期

- **所有权明确**：成员指针明确归属，`new` 对象指定 `parent`（QObject 父子链）或由唯一归属者析构；裸指针跨模块传递时注明"非拥有指针"（见 `DeviceController::m_client`）
- **智能指针**：跨线程/异步分发共享状态使用 `std::shared_ptr` + `make_shared`（见 EventBus 的 `DeviceState` 载荷）；本线程独占生命周期优先 `std::unique_ptr`
- **线程安全**：工作线程中共享的数据（如 `RtspThread` 的帧缓冲）用 `QMutex` 保护；UI 控件只能在主线程更新
- **退出清理**：程序退出须安全终止后台线程与网络对象（`DeviceManager::removeAllDevices()`），严禁野线程在进程结束仍在运行

### 4.4 错误处理

- **协议边界**：解析数据前必须校验长度/帧头/校验和（如 `processBuffer()` 的 10MB/50MB 上限），防止异常数据导致越界与 OOM
- **设备参数**：所有用户可输入参数经 UI 控件 `max/min` 或代码 `clamp` 约束在物理合法范围
- **网络错误**：连接失败走统一错误出口（信号 + 状态栏反馈），不静默吞错

### 4.5 Git 提交规范

- **提交信息**：`type(scope): 描述`。type 取值：`feat` 新功能 / `fix` 修复 / `refactor` 重构 / `docs` 文档 / `chore` 工具与杂项
- **示例**：`fix(core): include DeviceManager.h in mainwindow.cpp`、`docs: 整合架构索引与开发文档`
- **原则**：一次提交一个逻辑变更；文档与代码独立提交；不提交子模块未确认的改动（如 `thirdparty/aws-sdk-cpp`）
