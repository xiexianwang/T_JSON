# T-JSON 架构债优化详细设计

## 1. 文档定位

本文档是 `docs/架构债优化方案.md` 的独立详细设计，针对当前仍未解决的架构债进行实施分解。

本文档不重复设计已经完成的帧编解码拆分、协议组包拆分、多设备电机信号动态绑定和 RTSP 线程等待修复，只规定这些能力在后续重构中不得回退。

## 2. 优化范围

### 2.1 处理范围

- `DeviceContext`、`DeviceManager` 的设备生命周期和销毁顺序。
- `default_device` 的业务依赖和当前设备上下文管理。
- `MainPresenter.cpp` 的设备、 电机、地图和 AI 职责混合。
- `mainwindow.cpp` 的导航、对话框、窗口和部分业务协调职责混合。
- Presenter 与具体视频、地图 Widget 的边界收紧。
- 生命周期、多设备切换和服务拆分的测试补齐。

### 2.2 非目标

- 不修改 TCP 8089、RTSP、Pelco-D、VISCA、MODBUS-RTU、STM32-TCP 协议行为。
- 不调整地图算法参数、轨迹抽稀阈值或视频坐标映射算法。
- 不进行大规模命名重构。
- 不删除 AWS SDK、`s3uploader.*` 等尚未完成产品确认的模块。
- 不以文件行数达标作为唯一完成条件。

## 3. 当前问题与约束

### 3.1 当前问题

1. `MainPresenter.cpp` 同时承担设备调度、电机控制、状态分发、AI 处理和地图业务。
2. `mainwindow.cpp` 同时承担窗口生命周期、控件初始化、导航、对话框和部分设备/UI 协调。
3. `DeviceContext` 析构、`DeviceManager` 删除和业务关闭流程存在重复关闭的可能，需要明确唯一关闭入口。
4. RTSP 关闭虽然已有等待和中断回调，但需要补充设备删除、自动重连等待和程序退出场景验证。
5. `default_device` 仍可能从启动占位标识扩散为业务判断依据。
6. Presenter 已使用 `IMainView`，但后续接口仍需避免暴露具体 Widget 类型。

### 3.2 强制约束

- 依赖方向保持为 UI → 业务上下文 → 基础设施，`core/` 不依赖外层。
- UI 不直接调用 `TJsonClient`、`DeviceController`、`RtspThread` 等底层对象。
- 网络操作保持异步，不新增 UI 线程阻塞等待。
- 所有异步设备事件携带 `deviceId`，并在消费端校验目标设备。
- 每次只处理一个职责组，每次修改后立即构建和测试。
- 每个重构节点保持独立提交，失败时只回滚当前节点。

## 4. 总体路线

采用安全渐进式重构路线：

```text
建立基线
    ↓
收口 DeviceContext 生命周期
    ↓
收口当前设备和多设备信号
    ↓
提取 PresenterDeviceService
    ↓
提取 PresenterMotorService
    ↓
提取 PresenterMapService
    ↓
提取 MainWindowNavigation 和 MainWindowDialogService
    ↓
收紧 Presenter/View 语义接口
    ↓
补齐生命周期、多设备和服务测试
```

推荐原因：先稳定异步对象和设备选择，再移动业务职责，最后改变 View 接口，能够避免把生命周期问题和接口变更叠加在同一批改动中。

## 5. 生命周期优化

### 5.1 统一关闭入口

建议增加 `DeviceContext::shutdown()`，由 `DeviceManager` 在删除设备时调用。关闭顺序为：

```text
停止业务定时器
    → 停止 PTZ 转发
    → 关闭电机 TCP 和串口
    → 停止 RTSP 并等待线程退出
    → 断开 TJsonClient 并取消自动重连
    → 标记上下文为 Stopped
```

`DeviceContext::~DeviceContext()` 保留兜底关闭，但不再作为正常业务关闭的主要入口。关闭操作必须具备幂等性，重复调用不能重复创建资源、发送指令或触发错误提示。

### 5.2 关闭状态

`DeviceContext` 增加内部生命周期状态：

- `Active`：允许连接、视频和控制操作。
- `ShuttingDown`：拒绝新的连接、视频和控制请求，等待已有异步对象退出。
- `Stopped`：对象不可再使用，等待销毁。

在 `ShuttingDown` 和 `Stopped` 状态下，定时器回调必须先检查状态，避免关闭后继续发送初始化指令或触发重连。

### 5.3 RTSP 线程契约

继续使用现有停止标志、条件变量唤醒、FFmpeg 中断回调和 `wait(3000)` 机制，并补充以下约束：

- `closeStream()` 必须关闭自动重连。
- 线程退出前不释放线程使用中的 FFmpeg 资源。
- 线程超时不能静默删除对象，必须记录设备上下文和线程状态。
- `openStream()` 在旧线程未安全退出前不能启动新的解码线程。
- 程序退出和设备删除使用同一关闭契约。

### 5.4 生命周期验证场景

- 删除未连接设备。
- 删除 TCP 已连接设备。
- 删除正在 RTSP 拉流的设备。
- RTSP 自动重连等待期间删除设备。
- 多个设备同时在线时退出程序。
- 设备删除后不再收到状态、AI、视频和电机信号。

## 6. 多设备上下文优化

### 6.1 当前设备规则

`default_device` 只能作为启动时的初始设备 ID，不能作为业务类型或特殊设备判断条件。所有业务入口统一执行：

```text
当前设备 ID
    → DeviceManager::getDevice(deviceId)
    → DeviceContext 业务 API
```

禁止通过默认设备推断当前控制对象，也禁止在 MainWindow 中直接维护一份独立的当前设备状态。

### 6.2 设备切换顺序

```text
记录旧设备 ID
    → 解绑旧设备的 Presenter 临时信号
    → 更新当前设备 ID
    → 绑定新设备信号
    → 刷新新设备完整状态
    → 绑定视频控件
    → 刷新地图、仪表盘和连接状态
```

所有旧设备异步事件必须通过 `deviceId` 过滤，不能因为事件到达时间晚而刷新当前设备 UI。

### 6.3 设备删除行为

- 删除当前设备前先解绑 Presenter 信号。
- 清理视频宫格中该设备的帧和绑定关系。
- 清理地图中该设备的位置、目标和轨迹展示。
- 若仍有设备，选择明确的剩余设备；否则进入无当前设备状态。
- 删除后禁止通过旧指针发送命令。

## 7. MainPresenter 拆分

### 7.1 MainPresenter 保留职责

MainPresenter 最终只保留：

- 初始化和服务对象协调。
- 接收 MainWindow 的业务命令。
- 选择当前 `DeviceContext`。
- 连接和断开服务信号。
- 将服务结果转发给 `IMainView`。
- 管理当前设备 ID和界面状态分发。

### 7.2 PresenterDeviceService

负责：

- 设备连接、断开和重连。
- 当前设备切换。
- 设备状态订阅。
- 设备初始化参数下发。
- 状态转换为展示模型。
- 设备销毁前的信号解绑。

不负责 PTZ、电机细节、地图坐标计算和具体 Widget 操作。

### 7.3 PresenterMotorService

负责：

- PTZ 移动和停止。
- 镜头变倍和聚焦。
- 电机通道初始化、切换和静音状态。
- 雨刷控制。
- 预置位和零点标定。
- 电机结果、错误和指令日志信号。

服务不读取 Qt 控件，不决定弹窗或页面显示方式。预置位、电流等参数由 Presenter 或 View 接口转换为业务参数后传入。

### 7.4 PresenterMapService

负责：

- AI 数据业务转换。
- 目标距离和方向计算。
- 设备位置转换。
- 地图目标、FOV、轨迹展示模型生成。
- 轨迹抽稀。
- AI 超时和目标消失处理。

地理算法继续使用 `core/GeoCalculator`。服务只输出地图业务数据，不调用 `QWebEngineView`、Leaflet 或 JavaScript。

### 7.5 拆分原则

- 保留 MainPresenter 现有公开命令接口，降低一次性影响范围。
- 先移动职责，不同时改变协议和状态模型。
- 新服务不得依赖 `MainWindow`、`VideoWidget`、`VideoGridWidget` 或 `MapWidget`。
- 服务输出先由 MainPresenter 转发，待行为稳定后再直接接入语义化 View 接口。

## 8. MainWindow 拆分

### 8.1 MainWindow 保留职责

- Qt Designer 控件管理。
- 窗口构造、显示和销毁。
- `resizeEvent`、`closeEvent`、`eventFilter`。
- 控件值读取和展示。
- View 接口实现。

### 8.2 MainWindowNavigation

负责：

- 监控、日志、设置等区域的切换。
- 地图显示开关。
- 导航按钮状态。
- 页面预留入口。

第一轮只迁移无设备状态依赖、边界清楚的导航逻辑。

### 8.3 MainWindowDialogService

负责：

- 设置对话框。
- 指令日志对话框。
- 错误提示。
- 连接提示。
- 对话框重复打开、关闭和对象归属。

第一轮不迁移复杂控件初始化、视频布局和主窗口事件过滤，避免同时改变 UI 行为。

## 9. Presenter/View 接口收紧

### 9.1 目标接口

逐步把具体控件访问替换为业务语义方法，例如：

```text
showVideoFrame(deviceId, frame)
showDeviceState(deviceId, state)
showMapTargets(targets)
showTrackPoint(point)
showDevicePosition(position)
showConnectionState(deviceId, state)
```

接口参数优先使用 `DeviceState`、`TrackPoint`、`MapTarget`、`DevicePosition` 等轻量值对象或现有数据模型。

### 9.2 禁止暴露的类型

- `VideoWidget*`
- `VideoGridWidget*`
- `MapWidget*`
- `Ui::MainWindow*`
- `TJsonClient*`
- `DeviceController*`

### 9.3 迁移策略

1. 先增加语义化接口，不删除旧接口。
2. 将 MainPresenter 的调用逐个迁移到新接口。
3. 验证视频、地图和仪表盘行为。
4. 删除没有调用者的具体控件访问接口。
5. 检查 Presenter 头文件不再包含具体 Widget 头文件。

## 10. 分阶段实施节点

### 节点 0：建立基线

记录工作树、Debug 构建、CTest、主程序启动、两个大文件行数和已知人工场景。

通过条件：基线构建成功，现有失败项有记录。

### 节点 1：生命周期安全收口

修改 `DeviceContext`、`DeviceManager`、RTSP 相关关闭契约，增加设备删除和程序退出验证。

通过条件：无野线程、无死锁、无销毁后回调。

### 节点 2：当前设备和多设备上下文收口

清理 `default_device` 业务依赖，统一设备 ID 过滤、切换绑定和删除后的 UI 清理。

通过条件：双设备切换、PTZ、电机、视频和状态均不串设备。

### 节点 3：提取 PresenterDeviceService

迁移设备连接、状态和初始化逻辑，保留 MainPresenter 原有公开接口。

通过条件：设备连接和状态分发行为不变。

### 节点 4：提取 PresenterMotorService

迁移 PTZ、镜头、电机、雨刷、预置位和电机信号处理。

通过条件：控制行为、协议组包和日志行为不变。

### 节点 5：提取 PresenterMapService

迁移 AI、目标距离、设备位置和轨迹业务，保持现有抽稀参数不变。

通过条件：目标、FOV、轨迹和 AI 超时显示不变。

### 节点 6：提取 MainWindow 导航和对话框

新增 `MainWindowNavigation` 和 `MainWindowDialogService`，暂不迁移复杂视频布局。

通过条件：导航、设置、日志和错误提示行为不变。

### 节点 7：收紧 View 接口

采用语义化展示方法替换具体 Widget 访问，删除无调用者的过渡接口。

通过条件：Presenter 不依赖具体 Widget，View 仍能完整展示设备状态。

## 12. 风险与回滚

### 12.1 主要风险

- Qt 信号重复连接。
- 服务对象持有失效的 `DeviceContext*`。
- 旧设备事件刷新新设备 UI。
- RTSP 线程关闭超时。
- 地图和 AI 更新顺序改变。
- MainWindow 关闭流程重复执行。

### 12.2 控制措施

- 所有异步回调携带 `deviceId`。
- 切换和删除前显式解绑信号。
- 新服务不持有 View 具体控件指针。
- 每个节点一个独立提交。
- 不跨节点混合接口重命名。
- 失败时只回滚当前节点，不覆盖其他用户改动。

### 12.3 推荐提交序列

```text
refactor: 固化架构债优化基线
fix(service): 收口 DeviceContext 生命周期
fix(ui): 收口当前设备与多设备信号
refactor(presenter): 提取设备服务
refactor(presenter): 提取电机服务
refactor(presenter): 提取地图服务
refactor(ui): 提取主窗口导航逻辑
refactor(ui): 提取主窗口对话框逻辑
refactor(ui): 收紧 Presenter 与 View 接口
test(service): 补充设备生命周期与多设备测试
docs: 增加架构债详细优化设计
```

## 13. 完成定义

本方案完成不以文件行数下降为唯一依据，必须同时满足：

1. 生命周期关闭顺序明确且经过设备删除、RTSP 和程序退出验证。
2. 当前设备通过显式设备 ID 管理，不依赖 `default_device` 特殊语义。
3. Presenter 业务职责已按设备、电机、地图分组并可独立测试。
4. MainWindow 导航和对话框职责已从大文件中下沉。
5. Presenter/View 使用语义化接口，不暴露具体 Widget 或底层设备对象。
6. 现有协议、设备控制、视频、AI 和地图行为保持一致。
7. 构建、单元测试、集成测试和人工回归全部通过。
