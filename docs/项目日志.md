## 2026-08-14 · 架构债第一批落地（生命周期收敛 + 默认设备硬编码消除）

### 1. 解决了什么问题 / 实现了什么功能

- **生命周期安全（P0 高风险）**：
  - `DeviceContext::stopConnection()` 统一停止顺序：系统参数/`AI 清理定时器` → `PtzForwarder::stop()` → `DeviceController::closeMotorTcp()/closeMotorSerial()` → `RtspThread::closeStream()` → `TJsonClient::disconnectDevice()`；TCP 侧无论当前是否已连接都无条件调用 `disconnectDevice()`，确保取消自动重连定时器。
  - `DeviceManager::removeDevice()/removeAllDevices()` 改为先 `stopConnection()` 再**同步 `delete ctx`**，替换原 `deleteLater()` 后立即清容器的竞态写法。
  - `RtspThread`：`m_mutex` 提升 `mutable`，新增 `bool stopRequested() const`；`closeStream()` 加锁置停止标志后 `wait(3000)`（非线程自调用时，超时 `qWarning`）；`openStream()` 先 `closeStream()` 确保旧线程退出再 `start()`，`m_connecting` 移入锁内；析构不再自行 `wait()`；run() 主循环与解码循环改用 `stopRequested()`，URL 读取加锁拷贝。
- **默认设备硬编码收敛（P1）**：`mainwindow.cpp` 中视频网格 `bindDevice`、`getWidget("default_device")`、清帧/断开逻辑全部改用 `m_presenter->currentDeviceId()`；`MainPresenter.cpp` 的 `on_btnVideoDisconnect_clicked()`、`onComboWorkModeChanged()` 改 `m_currentDeviceId`；`onDeviceDoubleClicked()` 先更新 `m_currentDeviceId` 再 `bindDevice` → `startConnection` → `openStream`。全 src 仅剩 `MainPresenter.cpp:19` 构造函数初始化 `m_currentDeviceId("default_device")` 保留。
- **前置里程碑（本会话）**：`8d200cc refactor: 迁移 PTZ/镜头按钮到 Presenter 并移除过渡期访问器`（PTZ 八方向/镜头控制/PTZ 转发启动/状态查询收口进 Presenter，`motorController()/tcpClient()/videoStream()/ptzForwarder()` 降为私有）。
- **文档基线**：`ARCHITECTURE.md` §8 债务表更新（新增"生命周期风险""多设备收口"，删除"未提交改动"行）；`docs/CHANGELOG.md` 更新提交状态与下一步计划；新增长期方案 `docs/架构债优化方案.md`（P0-P3 + 6 阶段路线）。
- **构建验证**：MSVC2022 x64 Debug 构建通过，`LSSVideoManager.exe` 链接 + windeployqt 部署成功；`git diff --check` 通过。
